# Seeded World Generation — Design Spec

**Date:** 2026-04-05
**Status:** Approved (brainstorming)

---

## Summary

Replace the static village map with a client-side procedural world generator. Given a seed, the generator produces a large (120x90) Stardew Valley-style world with organic terrain, zone-based object placement, and whole-building sprites. Runs entirely in the browser — no Node.js or server dependency for generation.

## Goals

1. Remove all remaining procedural canvas drawing code (bridge, palette, helpers)
2. Replace tile-assembled buildings (wall/door/window/roof) with single-sprite buildings from PixelLab
3. Implement deterministic seeded map generation in-browser using Simplex noise
4. Enable per-classroom unique worlds via seed

## Non-Goals

- Interior maps / portal system (future work)
- Multiplayer map sync (server already manages classroom state)
- Map editing tools

---

## Architecture

### Generation Pipeline

```
Teacher sets seed in dashboard
        |
Student loads game
        |
Engine passes seed + dimensions to WorldGenerator
        |
WorldGenerator outputs mapData (full format, see below)
        |
TileMap renders it (existing renderer with performance optimization)
```

### WorldGenerator Class (`public/js/game/world-gen.js`)

Single export: `generateWorld(seed, width, height)` returning a map data object compatible with the existing `TileMap` constructor.

**Output format must match existing TileMap contract:**
```javascript
{
  name: 'generated',
  width: 120,
  height: 90,
  tileSize: 16,
  layers: {
    ground: [/* 90 rows x 120 cols */],
    objects: [/* 90 rows x 120 cols */],
    collision: [/* 90 rows x 120 cols */]
  },
  npcs: [{ id, name, x, y, sprite }],
  playerStart: { x, y }
}
```

**Deterministic:** Same seed + dimensions = identical output every time.

## Terrain Generation

### Simplex Noise

Inline a minimal 2D Simplex noise implementation (~50 lines, no npm dependency). Seeded via the classroom seed.

### Heightmap to Terrain

Two noise layers combined:

1. **Base heightmap** — large-scale terrain shape (low frequency)
2. **Detail layer** — small-scale variation (high frequency, low amplitude)

Combined value (0.0–1.0) maps to terrain IDs:

| Range | Terrain | ID |
|-------|---------|-----|
| 0.00–0.25 | Water | 4 |
| 0.25–0.35 | Sand | 5 |
| 0.35–0.75 | Grass | 0 |
| 0.75–1.00 | Dirt | 2 |

Grass light (ID 1) applied randomly (~15%) within grass areas for visual variation.

Bridge (ID 6) is removed as a ground tile — bridges become objects.

**Cobblestone (ID 3) is NOT generated by noise.** It is stamped onto the ground layer during zone placement — only in the Town zone center, as a rectangular plaza area. This avoids the missing dirt↔cobblestone tileset problem.

### Terrain Adjacency Guarantee

By design, only these terrain pairs can be adjacent:
- Water ↔ Sand (covered by `water-sand` tileset)
- Sand ↔ Grass (covered by `sand-grass` tileset)
- Grass ↔ Dirt (covered by `grass-dirt` tileset)
- Grass ↔ Cobblestone (covered by `grass-cobblestone` tileset)

Dirt and cobblestone are **never adjacent** — cobblestone plazas are always surrounded by a grass buffer of at least 1 tile. The generator enforces this during town zone stamping.

Sand and dirt are **never adjacent** — dirt only appears in high-elevation areas (center), sand only appears around water (low elevation). The grass band between them is guaranteed by the wide grass threshold (0.35–0.75).

### Terrain Properties

- Water bodies form naturally from low noise values
- Sand rings water as a shoreline (automatic from threshold adjacency)
- Grass is the dominant terrain (~40% of map)
- Dirt clusters near center (town area) via a radial bias: noise values near map center get a boost toward higher thresholds

## Zone Detection

Zones are **emergent** from terrain, not pre-assigned rectangles.

After terrain generation, scan the map to identify zones:

### Zone Rules

| Zone | Detection Rule | Bias |
|------|---------------|------|
| Beach | Sand tiles adjacent to water | Wherever water appears |
| Forest | Grass tiles within 10 tiles of map edge | Map perimeter |
| Town | Largest connected dirt cluster near center + stamped cobblestone plaza | Center bias from radial boost |
| Farm | Grass tiles adjacent to town zone, not forest | Near town |
| Cave | Highest-elevation quadrant corner | One corner |

**Cave zone detection algorithm:** Divide the map into four equal quadrants (60x45 tiles each). Score each quadrant by counting dirt tiles. The quadrant with the highest score becomes the Cave zone (limited to a 15x15 area in that quadrant's corner). Ties broken by quadrant index order: NW > NE > SW > SE.

**Forest band:** 10 tiles from map edge (not 15), producing ~3,600 tiles (~33% of map). Tree density reduced to 8 per 100 tiles to avoid viewport occlusion on small Chromebook screens.

Each tile gets tagged with at most one zone. Priority: Town > Cave > Beach > Farm > Forest > Wilderness (untagged grass).

### Collision Footprint Algorithm

For each placed building/object at anchor tile `(tx, ty)` with footprint `(fw, fh)`:
```
for dy in [0, fh):
  for dx in [0, fw):
    collision[ty + dy][tx + dx] = 1
    objects[ty + dy][tx + dx] = objId  // only at (tx, ty) anchor
```

Only the anchor tile `(tx, ty)` stores the object ID in `objects[][]`. The remaining footprint tiles get `collision = 1` but `objects = 0`. The renderer only draws the sprite once at the anchor position.

### Zone Density Tables

Each zone defines which objects to place and at what density (objects per 100 tiles):

**Forest:**
- Trees (ID 1, 2): 8 per 100 tiles
- Bushes: 3
- Tall grass: 5
- Mushrooms: 2
- Rocks: 2

**Town:**
- Shops (ID 6-8): 2-3 total, minimum 6 tiles apart
- Lamps: 3 per 100 tiles
- Benches: 2
- Signs: 1-2 total
- Barrels: 2

**Farm:**
- Farmhouse (ID 9-10): 1-2 total
- Barn (ID 11-12): 1-2 total
- Fences: 8 per 100 tiles
- Wells: 1 total

**Beach:**
- Dock (ID 15-16): 1 total, placed at water edge
- Rocks: 3 per 100 tiles

**Cave:**
- Cave entrance (ID 13-14): 1 total
- Rocks: 6 per 100 tiles

### Placement Rules

1. **Buildings** require a clear rectangular footprint (no overlapping objects, terrain must match zone)
2. **Minimum spacing** between buildings: 4 tiles
3. **Trees** need 2-tile spacing from buildings, 1-tile from each other
4. **Small objects** (flowers, grass, mushrooms) can be adjacent
5. **Bridges** placed where a dirt path crosses a 1-2 tile wide water gap. Horizontal gap → Bridge H (ID 17), vertical gap → Bridge V (ID 18)
6. **Player start** placed in town zone on a walkable tile

### Collision Generation

Auto-generated from terrain + object placement:
- Water tiles: blocked
- Object footprints: blocked per footprint algorithm above
- Small decorations (flowers, grass, mushrooms): walkable (footprint 1x1 but collision stays 0)
- Map border: 1-tile blocked perimeter

## NPC Placement

3 NPCs placed in fixed zone positions:
- **Teacher NPC** — in town zone, near a shop
- **Shopkeeper NPC** — adjacent to a shop building
- **Librarian NPC** — in farm or town zone

NPC interaction uses the existing encounter trigger system (proximity check + API call). No portal stub needed.

NPC data format unchanged: `{ id, name, x, y, sprite }`.

## Renderer Performance

The map grows from 40x30 (1,200 tiles) to 120x90 (10,800 tiles). On Chromebook hardware this requires optimization.

### Ground Layer Baking

After placing all ground sprites during `render()`, bake the entire ground layer to a single `PIXI.RenderTexture`:

```javascript
const groundContainer = new PIXI.Container();
// ... add all ground sprites to groundContainer ...
const renderTex = PIXI.RenderTexture.create({ width: mapW, height: mapH });
app.renderer.render(groundContainer, { renderTexture: renderTex });
// Replace thousands of sprites with one
const bakedGround = new PIXI.Sprite(renderTex);
this.container.addChildAt(bakedGround, 0);
groundContainer.destroy({ children: true });
```

This reduces ground draw calls from ~10,800 to 1.

### Object Layer

Object sprites remain individual (for future interactivity). At ~970 objects across the full map, only ~50-100 are visible in the viewport at any time. PixiJS culls offscreen sprites automatically with `container.cullable = true`.

## Testing

1. **Determinism test:** Generate two maps with same seed, verify identical output
2. **Visual test:** Load game, verify terrain looks organic with smooth Wang transitions
3. **Adjacency test:** Verify no unsupported terrain pairs appear (no dirt↔cobblestone, no sand↔dirt)
4. **Zone test:** Verify buildings only appear in appropriate zones
5. **Collision test:** Walk around, verify buildings/water/trees block movement, decorations don't
6. **Performance test:** On Chromebook, verify 60fps with 120x90 map after ground baking
7. **Edge cases:** Very small maps (20x15), very large maps (200x150), seed=0
